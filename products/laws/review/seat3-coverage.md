# Seat 3 — spec coverage and operadic structure

Reviewer: independent (seat 3 of 3). Scope: does the 11-stage operad in `products/laws/src/lib.rs` + `wiring.rs` re-compose to the product described in `products/SPEC.md` (v0.1) and `specv1.md`? Evidence is file:line or command output. Baseline: `RUSTUP_TOOLCHAIN=stable cargo test --offline` in `products/laws` → 12/12 pass (the pinned 1.85.1 toolchain cannot be downloaded on this box; the tests pass on stable). All 12 tests check the tree's *internal* well-formedness; none checks it against either spec, which is the gap this seat exists for.

Verdict in one line: the operad is a faithful model of **one call of `sheaf analyze` turned into one receipt**. It is not yet a model of the product: the second core capability (harmonic extension) is wired in and then dropped on the floor, and roughly half of the spec's user-facing capabilities (explain, diff/baseline, write-back, error/crash path, adapters, transport, scheduling, Studio interaction) have neither a stage nor a law.

## 3. Missing stages — proposed signatures (summary of S3-02..S3-06, S3-09)

```
Ingest  : (Corpus)                               → DomainGraph | Rejected      (S3-06; owner Products; Memory/Recon refine)
Analyze : (ValidSpec, CorePolicy, Boundary?)     → Outcome = Report | CoreError (S3-01, S3-04, S3-12; replaces Analyze + Extend)
Explain : (Finding)                              → Explanation                 (S3-02)
Diff    : (Finding, Finding)                     → Delta                       (S3-03; the one legitimate parallel composition: both inputs come from independent full-pipeline runs)
Fill    : (Finding, DomainGraph)                 → DomainGraph' | Ask          (S3-05)
Attribute gains a Circ input                                                   (S3-08)
Surface : functor on the whole composite, not a stage (G8)                     (S3-09)
Schedule: out of the operad; it is iteration of the composite + Diff; say so in LAWS.md (C17)
```

With these the COMPOSE witness reads: `Receipt ∘ Join ∘ Attribute ∘ Classify ∘ Quantize ∘ Circulate ∘ Certify ∘ Analyze ∘ Validate ∘ Encode ∘ Ingest`, then `Explain` and optionally `Fill` and `Diff` over the Finding — which is the product SPEC.md §4 describes. Today the witness stops at Receipt and does not include Extend's output.

## 4. Depth and explosion

- Too shallow: Certify (1 law), Validate (1 law), Receipt→Join edge (0), Analyze→Quantize edge (0) — see S3-10, S3-16.
- Correct depth: Classify (1 stage law, 7 atoms, 2 product leaves) and Circulate are well-proportioned subtrees.
- Nothing is too deep; the ≤ 3 cap holds (`depth_is_capped…` passes). The cap will be strained by S3-16's Certify atoms with product refinements (e.g. a Recon refinement of `A.certify.unique-null`) — that is depth 3, still legal.
- Flat where it should be a subtree: `holes()` (lib.rs:317-325) is a flat list of five strings outside the ontology; H4 and H5 describe laws that the tree should contain as `Status::Hole` nodes so `no_law_is_derived_through_a_hole` can actually fire. Today `Status::Hole` is never constructed (`grep -c "Hole," lib.rs` on law rows → 0), so that test is vacuous.
